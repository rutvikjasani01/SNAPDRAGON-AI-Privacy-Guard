# Qualcomm AI Hub Integration Path

This document outlines the architectural path and procedures for integrating optimized machine learning models into the **Snapdragon AI Privacy Guard**. By utilizing the [Qualcomm AI Hub](https://aihub.qualcomm.com/), this application can leverage local Snapdragon® hardware accelerators (CPU, GPU, NPU) for performant, privacy-first, on-device inference.

> **Disclaimer:** This project is an independent student application. It is not an official Qualcomm product, nor does it imply an official partnership with Qualcomm Technologies, Inc. References to Snapdragon® and Qualcomm® AI Hub are intended strictly to describe technical integration capabilities and deployment targets.

---

## 1. Model Selection

The application's `ai/model_manager.py` abstraction layer is designed to swap the underlying mock/CPU routines with production-ready models. 

When selecting models from the Qualcomm AI Hub, focus on the following categories suitable for privacy workloads:
*   **OCR and Text Extraction:** Lightweight Vision/Transformer models capable of bounding-box regression and text recognition.
*   **Entity Detection:** NLP-focused models (e.g., MobileBERT, DistilBERT) optimized for token classification (Named Entity Recognition - NER).
*   **Image Redaction Support:** Semantic segmentation models for isolating specific objects/regions beyond simple bounding boxes if required in future updates.

---

## 2. Optimization Path

Once a PyTorch, TensorFlow, or ONNX model is selected, it must be optimized for Snapdragon hardware to ensure battery efficiency and low latency.

1.  **Export the Model:** Prepare the model in a standard format (ONNX or PyTorch TorchScript).
2.  **Submit to AI Hub:** Use the `qai-hub` Python client to submit the model for compilation.
    ```python
    import qai_hub as hub
    
    # Example snippet for conceptual understanding
    model = hub.upload_model("path/to/my_ner_model.onnx")
    compile_job = hub.submit_compile_job(
        model=model,
        device=hub.Device("Snapdragon X Elite Compute Architecture"), # Target device
        options="--target_runtime qnn" # Target Qualcomm Neural Network runtime
    )
    compiled_model = compile_job.get_target_model()
    ```
3.  **Quantization:** Where possible, leverage INT8 quantization during the compilation phase to drastically reduce memory bandwidth and increase NPU throughput, critical for responsive UI experiences during document scanning.

---

## 3. Deployment Path

Integrating the compiled model into the application's runtime environment.

1.  **Download Asset:** Download the `.bin` or `.so` artifacts generated by the compile job.
2.  **Runtime Integration:** The backend (FastAPI in Python) will interact with the compiled models using the appropriate runtime SDK (e.g., Qualcomm Neural Processing SDK or ONNX Runtime with QNN Execution Provider).
3.  **Manager Registration:** Register the new runtime environment inside `ai/model_manager.py` within the `ModelRuntime` enum (e.g., `ModelRuntime.NPU`), shifting away from `ModelRuntime.MOCK`.
4.  **Inference Execution:** Map the backend application tensor inputs (image bytes or tokenized strings) to the expected input dimensions of the compiled model.

---

## 4. Profiling Path

To ensure the application meets the "Performance" UI metrics truthfully, profiling is required.

1.  **AI Hub Profiling:** Use the AI Hub to generate comprehensive performance profiles on real hardware hosted in the Qualcomm device cloud before local deployment.
    ```python
    profile_job = hub.submit_profile_job(
        model=compiled_model,
        device=hub.Device("Snapdragon X Elite Compute Architecture")
    )
    profile_data = profile_job.get_profile()
    print(f"Estimated Inference Time: {profile_data.inference_time} ms")
    ```
2.  **Local Telemetry:** Implement native telemetry inside `ai/model_manager.py` (which currently tracks basic `latency_ms`) to log execution times locally. 
3.  **UI Feedback:** Surface these real profiling metrics directly to the user in the `/performance` route to demonstrate the true on-device advantage (low latency, zero network overhead).
